# ExtendScript-виконавець Рівня 2

`inkforge_layout.jsx` — скрипт для Adobe InDesign, що споживає
`layout_plan.json`, записаний Python-планувальником (`inkforge-plan`, див.
`src/inkforge/layout_engine/`).

## Статус: частковий, не перевірений на реальному InDesign

У середовищі, де велась розробка, немає встановленого InDesign — цей файл
**ще не запускався на реальному документі**. Реалізовано і має сенс
перевірити:

- **Preflight шрифтів** — звіряє `fonts_installed`/`fonts_substituted` з
  профілю газети (прокинуті через `layout_plan.json`) з реальним статусом
  шрифтів на машині верстальниці (`app.fonts`).
- **Колонтитул** — проставляє дату й номер випуску в наперед створені текстові
  змінні документа (`Type > Text Variables`, імена `InkForge_IssueDate` /
  `InkForge_IssueNumber` — створюються один раз вручну у файлі-основі).
- **Геометричне групування статей + relink фото** — `findArticleClusters()`
  групує фрейми сторінки навколо кожного заголовка (алгоритм валідовано
  офлайн на IDML-зразках MIF, див. `docs/architecture.md`, "Групування
  кількох статей..."), а `applyArticlesToPage()` зіставляє знайдені кластери
  зі статтями `layout_plan.json` за порядком читання й переприв'язує фото
  (`itemLink.relink`) на нові файли. Працює лише для газет із розв'язаною
  `paragraph_style_roles` (наразі MIF); якщо кількість кластерів не
  збігається з кількістю запланованих статей — сторінка пропускається без
  змін (захисний принцип "не вгадувати").

## Свідомо НЕ реалізовано

**Вставка реального тексту заголовка/ліда/тіла статті.** Групування фреймів
за ролями й геометрією тепер зіставляє "цей заголовковий фрейм належить оцій
статті з маніфесту", але сам текст (окрім фото) туди ще не вставляється —
`content_checker` (Рівень 1) наразі рахує лише метрики (`word_count`,
`char_count`, `has_lead_paragraph`), а не структурований поділ вихідного
`.docx` на заголовок/лід/тіло. Без цього поділу вставляти в конкретний
фрейм конкретного відповідного шматка тексту нема з чого. Це окрема майбутня
задача (розширення Рівня 1).

Також не реалізовано: динамічне додавання/видалення фреймів під новий обсяг
тексту (Horizontal Scale в межах 97–102% тощо) — це має сенс лише після
того, як з'явиться реальний текст для вставки.

Для Духовності групування взагалі не застосовується: там навіть базова мапа
"стиль -> роль" відсутня (див. `profiles/dyhovnist.yaml` і
`docs/architecture.md`) — потрібен окремий аналіз character-style/локальних
override, щоб знайти механізм розрізнення заголовок/тіло.

**Наступний крок для завершення цієї частини:** розширити Рівень 1, щоб
`manifest.json` ніс структурований поділ статті (заголовок/лід/тіло), а не
лише агреговані метрики — тоді `applyArticlesToPage()` зможе вставляти
реальний текст у вже правильно знайдені фрейми.

## Як (у майбутньому) запускати вручну

1. У Python: `inkforge-check` → `manifest.json`, потім `inkforge-plan
   manifest.json --profile <id>` → `layout_plan.json`.
2. У InDesign: `Window > Utilities > Scripts` → User → запустити
   `inkforge_layout.jsx`.
3. Скрипт запитає файл-основу (`.indd` попереднього випуску) і
   `layout_plan.json` через діалог вибору файлу (або читає їх з
   `app.scriptArgs`, якщо їх передасть майбутній Рівень 3 GUI-launcher).
