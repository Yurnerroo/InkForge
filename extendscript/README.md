# ExtendScript-виконавець Рівня 2

`inkforge_layout.jsx` — скрипт для Adobe InDesign, що споживає
`layout_plan.json`, записаний Python-планувальником (`inkforge-plan`, див.
`src/inkforge/layout_engine/`).

## Статус: частковий, не перевірений на реальному InDesign

У середовищі, де велась розробка, немає встановленого InDesign — цей файл
**ще не запускався на реальному документі**. Реалізовано і має сенс
перевірити лише те, що не залежить від відсутньої поки мапи "фрейм на
сторінці -> роль статті":

- **Preflight шрифтів** — звіряє `fonts_installed`/`fonts_substituted` з
  профілю газети (прокинуті через `layout_plan.json`) з реальним статусом
  шрифтів на машині верстальниці (`app.fonts`).
- **Колонтитул** — проставляє дату й номер випуску в наперед створені текстові
  змінні документа (`Type > Text Variables`, імена `InkForge_IssueDate` /
  `InkForge_IssueNumber` — створюються один раз вручну у файлі-основі).

## Свідомо НЕ реалізовано

Розчищення старого вмісту фреймів і заповнення новими статтями/фото (з
relink фото та Horizontal Scale в межах 97–102%) — `applyArticlesToPage()` у
скрипті лишається заглушкою, яка лише логує намір. Причина: щоб реально
знайти "цей фрейм на сторінці 4 — це заголовок другої статті", потрібна
стабільна мапа `Self ID фрейма -> роль`, якої в `profiles/*.yaml` поки немає
(див. "Відкриті питання" у `docs/architecture.md`). Писати цю логіку без
такої мапи означало б вгадувати — свідомо цього уникаємо.

**Наступний крок для завершення цієї частини:** для кожної газети
проаналізувати конкретний автоматизований розворот на рівні IDML, зафіксувати
`Self` ID кожного фрейма й його роль (заголовок/текст/фото певної статті), і
додати цю мапу як нове поле профілю (`frame_roles` чи подібне) в
`profiles/schema.md` + відповідні `profiles/<id>.yaml`.

## Як (у майбутньому) запускати вручну

1. У Python: `inkforge-check` → `manifest.json`, потім `inkforge-plan
   manifest.json --profile <id>` → `layout_plan.json`.
2. У InDesign: `Window > Utilities > Scripts` → User → запустити
   `inkforge_layout.jsx`.
3. Скрипт запитає файл-основу (`.indd` попереднього випуску) і
   `layout_plan.json` через діалог вибору файлу (або читає їх з
   `app.scriptArgs`, якщо їх передасть майбутній Рівень 3 GUI-launcher).
