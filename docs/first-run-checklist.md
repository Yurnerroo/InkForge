# Чек-лист першого реального запуску (Рівень 3, on Windows + InDesign)

Це — практичний покроковий гайд для першого разу, коли верстальниця запускає
`inkforge-launcher` на своєму реальному комп'ютері з Adobe InDesign. Уся логіка
верстки й PDF-експорту вже написана й покрита 105 автотестами, але кроки 3 і 5
(ті, що керують самим InDesign через COM) ще жодного разу не запускались на
справжньому Windows+InDesign — цей документ існує, щоб перша спроба пройшла
керовано, а будь-яка проблема одразу давала зрозумілу відповідь "де саме
зламалось і що написати розробнику".

## Перед першим запуском

- [ ] Windows (не macOS) — COM-автоматизація InDesign працює лише на Windows.
- [ ] Adobe InDesign встановлено і хоч раз відкривався вручну (щоб перевірити
      ліцензію/активацію) до запуску launcher-а.
- [ ] Python встановлено, і в тому ж середовищі виконано:
      ```bash
      pip install -e ".[launcher]"
      ```
      Це підтягне `pywin32` — без нього кроки 3 і 5 одразу дадуть зрозумілу
      помилку "pywin32 не встановлено", а не зависнуть.
- [ ] Папка тижневого випуску підготовлена за конвенцією
      [content-structure.md](content-structure.md) (тексти + фото за іменем).
- [ ] `.indd`-файл цього випуску вже створено вручну (копія минулого номера,
      як і завжди) — Рівень 3 не створює `.indd` "з нуля".

## Крок 0 — запуск застосунку

```bash
inkforge-launcher
```

Має відкритись `http://127.0.0.1:8765` у браузері з формою (газета, папка
випуску, шлях до `.indd`). Якщо браузер не відкрився сам — відкрити цю адресу
вручну.

## Крок 1 — "Перевірити контент"

Не залежить від InDesign. Натиснути кнопку, перевірити звіт:

- [ ] Усі тексти/фото знайдено (немає "не знайдено пари" для очікуваних статей).
- [ ] Немає критичних попереджень про обсяг тексту чи роздільність фото, які
      виглядають несподівано.

Якщо тут щось не так — це проблема назв файлів/структури папки, не InDesign;
виправити файли й повторити крок.

## Крок 2 — "Побудувати план верстки"

Теж не залежить від InDesign. Перевірити підсумок:

- [ ] Кількість автоматизованих/ручних/спеціальних сторінок відповідає
      очікуванням для цього випуску та газети.
- [ ] Немає попереджень, які виглядають як помилка профілю газети.

## Крок 3 — "Зверстати в InDesign" (перший реальний тест COM)

**Це перший крок, який реально відкриває/використовує InDesign через COM.**

Перед натисканням:
- [ ] `.indd`-файл випуску закрито в InDesign (або взагалі InDesign не запущено) —
      щоб уникнути конфлікту "відкрито в іншому процесі".

Натиснути кнопку і спостерігати:

- [ ] InDesign сам запускається/активується, відкриває вказаний `.indd`.
- [ ] Видно, як текст і фото розкладаються по сторінках (без жодних ручних дій).
- [ ] Лог виконання скрипту в launcher-і не містить помилок.
- [ ] Відкрити сам `.indd` в InDesign і візуально перевірити 2-3 сторінки:
      текст на своєму місці, фото не розтягнуті/не обрізані криво, заголовок і
      підзаголовок (де є) виглядають правильно.

**Якщо щось пішло не так на цьому кроці** — це найважливіша інформація для
розробника. Записати:
1. Точний текст помилки з launcher-а (скопіювати повністю, не переказувати).
2. На якому саме етапі це сталось (відкриття `.indd`? розкладання конкретної
   статті? конкретна сторінка?).
3. Скріншот, якщо є щось візуально дивне в InDesign.

## Крок 4 — ручне доправлення

Це очікуваний, штатний крок — рушій ніколи не претендує на 100% автоматизацію.
Доправити вручну все, що виглядає не так, як завжди робиться для друку.
**Не закривати InDesign після цього** — крок 5 використовує вже відкритий
документ, щоб не загубити ці правки.

## Крок 5 — "Експорт друк-PDF" (другий реальний тест COM)

- [ ] `.indd` усе ще відкрито в InDesign (з правками з кроку 4).
- [ ] Натиснути кнопку, вказати шлях для збереження PDF.
- [ ] Перевірити, що PDF створився за вказаним шляхом.
- [ ] Відкрити PDF і перевірити колір: чи виглядає як звичний друк-PDF (CMYK,
      без надто яскравих/неприродних кольорів, які бувають при неправильній
      RGB→CMYK конвертації).
- [ ] За можливості — звірити з тим, як виглядав PDF минулого випуску,
      зробленого повністю вручну.

**Якщо помилка** — так само записати точний текст помилки й на якому кроці
(застосування пресету? конвертація кольору? сам експорт?) вона з'явилась.

## Після першого запуску

Незалежно від результату — повідомити розробника: що спрацювало, що ні, і
записані вище деталі помилок (якщо були). На основі цього буде видно, чи
COM-кроки готові до постійного використання, чи потребують доопрацювання під
конкретну версію InDesign/Windows на цьому комп'ютері.
